# The frozen kernel spec · conformance vectors

These files ARE the specification of the portable PrismPath kernel, expressed as data. They are
generated from the **Python reference implementation** by `../gen_conformance.py`
(deterministic: fixed seed, sorted keys; regeneration is byte identical unless semantics
changed), and any implementation claiming conformance must pass **every case bit-for-bit**:

- **`predicates.json`**: 1,112 `(condition, context) → true | false | "ERROR"` cases for the
  `when`-predicate evaluator: one curated case per semantic sharp edge (the classes a
  61,700-comparison differential fuzz found implementations diverge on; Python keywords as
  field names, `True`-constant vs `true`-field-name, bool/number equality, chained
  comparisons, substring/list/dict membership, truthiness of empty containers, escape tables,
  numeric spellings, list ordering past equal-but-unorderable elements, depth accounting)
  plus a seeded grammar-fuzz sample. `"ERROR"` means the sandbox rejects the predicate
  (PredicateError); at run time such an edge is non-matching, never a crash.
- **`flows.json`**: 107 full engine fixtures: a flow document plus scripted worker outcomes
  (`script` maps node → outcomes consumed in visit order, last repeats; `{"__raise__": msg}`
  throws, exercising the error tier, and `"__kind__"` names the exception class the engine hands the flow as
  `error_type`, RuntimeError when it is absent) → the reference engine's `{path, stopped, pending_node,
  spawn, cause}`. The first 27 are the frozen fixtures. The other 80 (`engine_surface_fixtures.py`)
  carry `opts`, the engine's `type_gate` and `max_transcript` options, and expect what those change as
  well: `reason` and `violations` (the pending decision of a `contract_violation`, cause 37),
  `transcript` and `state_dropped` (the persisted history after the bound), `guard_errors` (which
  guard of which node could not be evaluated, as `_guard_errors` records it, without the message) and
  `steps` (each step's node and target and its info: `used`, the edge in `cond`, and what the error tier added). A flow whose
  `@state_bound` is malformed expects `{error: message, error_class}`: the run does not start, and so for
  a worker error no edge handles (the worker's own class and message). An engine that
  does not implement the options skips a case that has `opts`.
- **`contract.json`**: 56 flows with the worker output contract `derive_contract` reads from them (each
  node's fields in the order the edges first read them, with type and routed values), the JSON Schema
  and the text it renders, and 21 worker outputs with the problems `validate_output` finds, in order.
  Generated by `../gen_contract_fixtures.py`; replayed by `prismpath-rs/tests/test_contract.rs`.
- **`parse_limits.json`**: the flow parser's input bounds (`PRISMPATH_MAX_FLOW_BYTES`, `PRISMPATH_MAX_NODES`,
  `PRISMPATH_MAX_EDGES`): 49 small documents under small caps with the nodes and edge counts or the `ParseError`
  message the reference gives (one at each cap, one over it, where each is counted, which is reached first), 6
  documents built from a rule to the default caps, at each and one over, and 21 strings an environment
  variable may hold with what `int()` makes of each. Generated by `../gen_parse_limits_fixtures.py`; replayed
  by `prismpath-rs/tests/test_parse_limits.rs`.
- **`locked_flows.json`**: 8 P1 fixtures: flows with semantic edges pinned by an embedded
  lockfile (synthetic 4-D unit vectors, model-free) plus a scripted `embedMap` for outcome
  vectors → locked-routing paths, `human_floor` suspensions, and `would_pick` evidence.
  Generated by `../gen_p1_conformance.py`; replayed by `run_p1_conformance.mjs`.
- **`safety.json`**: the guard layer's frozen vectors (deny/allow verdicts across the onion
  layers), consumed by the guard parity suites.
- **`capability.json`**: 7 cases pinning the **portability matrix** (`capabilityReport`): a flow →
  which targets it compiles to (python / portable / Level M hardware) + the blocking edges. Any
  `capabilityReport` must reproduce every target status and reason bit-for-bit.
- **`reach.json`**: 11 cases pinning three-valued **reachability** (`checkReach`): a flow (+ optional
  `assume`, `bound`, error/event toggles) → `{reachable: yes|may|no, proven}` per target. Witnesses are
  not frozen (BFS tie-order is an implementation detail); the verdict contract is.
- **`receipts.json`**: 251 receipt verification cases for signed root statements and flow manifests (`kind`
  merkle, trail, bundle, flow, floor, separation): the Merkle tree, audit
  logs with their statements and every way to tamper with them, receipt bundles (with `status` and the `index` and `covered` checks, and `problem` for a malformed bundle), flow manifests with each
  refusal cause, the version floor, and the instance key separation. Generated by `../gen_receipt_fixtures.py`
  from the live Python reference with fixed keys and clocks, so regeneration is byte identical; replayed by
  `prismpath/tests/test_receipt_vectors.py` and by `prismpath-hotswap-rs/tests/test_receipt_verify.rs`.
  The set is canon/2 (events with `ts_us` and the `encoding` tag, `prismpath-root-statement/3`, flow
  manifests signed over the canon/2 domain). canon/1 is retired and has no twin: the cases built from what it
  wrote (an event with a float `ts` and no tag, a `/1` statement, a log that crosses the migration) are in the
  set as refusals, with the findings the Python reference gives for them. What is written is canon/2, whose
  vectors are `canon2.json`.
- **`merkle_stream.json`**: the streaming form of the RFC 6962 root. Three leaf sets (the eight Certificate
  Transparency inputs, 300 32-byte leaves, 70 leaves of 0 to 69 bytes) and the root over every prefix of
  each, null for none, written by the Python batch tree and checked against `root_statement.MerkleAccumulator`
  before it is written. An accumulator fed the leaves one at a time must give each prefix root byte for
  byte. Generated by `../gen_merkle_stream_fixtures.py`; replayed by `prismpath/tests/test_merkle_stream.py`
  and `prismpath-rs/tests/test_merkle_stream.rs`, and in C by `prismpath-ebpf/test_merkle.c`
  (`make test-merkle`).

Verify the kernels:

```
node prismpath/portable/run_vectors.mjs          # JS, P0  -> CONFORMANT (27 flows, the 80 with engine options skipped)
node prismpath/portable/run_p1_conformance.mjs   # JS, P1  -> P1 CONFORMANT
node prismpath/portable/run_capability.mjs        # JS, portability matrix -> CONFORMANT
node prismpath/portable/run_reach.mjs             # JS, reachability       -> CONFORMANT
cd prismpath-rs && cargo run --bin conformance -- ../prismpath/portable/conformance
cd prismpath-go && go test ./...                 # 1112/1112 predicates, 27/27 flows (80 with engine options skipped)
cd prismpath-hotswap-rs && cargo test --test test_receipt_verify   # receipts.json, 245/245
cd prismpath-rs && cargo test --test test_merkle_stream            # merkle_stream.json, 378 prefix roots
```

(The capability/reachability corpora are parity contracts between the JS analyses and their
`model_check` reference; pinned from both sides by `test_capability_conformance.py` /
`test_reach_conformance.py` and the two `run_*.mjs` runners.)

Regenerate after an intentional semantics change (the resulting `git diff` is the
spec-change review):

```
python prismpath/portable/gen_conformance.py
python prismpath/portable/gen_receipt_fixtures.py   # receipts.json (needs the signing extra)
python prismpath/portable/gen_merkle_stream_fixtures.py   # merkle_stream.json
```

The pytest bridge (`prismpath/tests/test_conformance_vectors.py`) enforces both directions on every
run: the committed vectors must match a fresh regeneration from the live Python code (no
silent reference drift), and the port must pass the committed vectors (no silent port drift).
The Rust (`prismpath-rs/`) and Go (`prismpath-go/`) kernels already did exactly this; read the
files, pass every case; and any future kernel (WASM, or yours) is provably interchangeable the
same way, or measurably not.

The vectors also referee **declared-subset targets**: an implementation that cannot host the full
value domain (a fixed circuit, a table interpreter) declares the subset it certifies against,
passes every vector inside it, and publishes a machine readable reason for every exclusion; it
is never called conformant unqualified. The first example is the Level M hardware target
([`prismpath-hw/`](../../../prismpath-hw/README.md)): the C targets certify 147/1,112 predicate + 6/105
engine vectors, and the eBPF target the same 147 in kernel against the frozen expectations (October 2026).
The subset is frozen case by case in `prismpath-hw/declared_subset.json`, and both certification runners
and the drift test refuse a selection that differs from it, so it cannot shrink unnoticed. The RTL
certified 114/1,067 on corpus v1 on a board that no longer exists; that result stands as history.
