### #104 — the Facet codec measured on bare metal: the C Zeckendorf encoder verified and timed on all four MCU instruction sets (August 2026)

**Claim:** the wire encoder (Zeckendorf coding plus byte packing, the front half of Phase C2) runs on the same four MCU instruction sets that decide policies, byte identical to the Python reference, at microsecond scale on the 32 bit cores and under 2 ms worst case on the 8 bit floor tier. The FQ paper's §5.5 cost model for the codec on constrained hardware is now a measurement.

**Method:** `prismpath-hw/codec-bench/`. A portable C encoder (`zeck.h`: 78 entry u64 Fibonacci table F2..F79 covering the full 2^53 domain, 624 bytes of constant data, greedy subtraction, MSB first bit accumulator matching `packed.pack(bits, 8)`); `gen_bench_data.py` generates 64 four field events per workload WITH their expected wire bytes from the Python reference (typical: wire ints 1..6, 2.281 B/event; stress: a 1,000 cell codebook, wire ints 1..1001, 7.062 B/event); every target verifies all 128 rows byte for byte on device before timing, and a mismatch halts the bench. Timing: Uno R3 via Timer1 (64 us tick, 2,048 events per window), ESP32 via esp_timer, RP2350 via time_us_64 (65,536 events each), the RP2350 building both ISAs from one source file. Compiled -Os throughout.

**Result:** typical / stress ns per event: **ATmega328P 16 MHz: 462,718 / 1,756,625** (~7,400 cycles typical); **Xtensa LX6 240 MHz: 9,283 / 27,902**; **Cortex-M33 150 MHz: 5,338 / 14,870**; **Hazard3 RISC-V 150 MHz: 4,645 / 13,690** (~700 cycles typical). All four verified 128/128 corpus rows before timing. Bring up found and fixed an AVR RAM hazard: the corpus and table initially landed in `.data` (1,980 of the part's 2,048 bytes), starving the stack; moved to PROGMEM (`.data` 124 bytes). **Honest scope:** encoder only (on device decode unmeasured); a wall clock microbenchmark on one board per ISA at -Os, not a cycle exact WCET; the u64 table is the general implementation and a small symbol table would be faster; Merkle/SHA-256 stays literature cited; the FPGA shift register codec remains the unbuilt half of C2. Staged here, not yet OTS anchored. Provenance: `prismpath-hw/codec-bench/` (`zeck.h`, `bench_core.h`, `gen_bench_data.py`, `avr_bench.c`, `esp32/`, `rp2350/`, `results.md`); boards Uno R3, ESP-WROOM-32, Pico 2 W; avr-gcc, ESP-IDF v5.4, pico-sdk.

### #105 — million decision soak (continuity, not throughput): two native codec Vector pipelines run continuously for over a day with zero errors and ~1.8 MB of total wire (August 2026)

**Claim:** this is a *continuity* result, not a load or capacity result: at a deliberate soak cadence (~5 events/s per pipeline, ~11/s combined), the Facet codec compiled into Vector sustains continuous production shaped operation without error or drift over a day plus; throughput ceilings are measured elsewhere (#104 on MCUs, 132 to 182 ns in kernel). Specifically: two independent encode/decode pipelines ran unattended for 31 and 27 hours, decoding 1,043,442 decisions between them with zero bad lines, zero decode errors, zero log errors, and flat memory, while the total wire traffic for the entire run was ~1.8 MB.

**Method:** `integrations/vector/soak/`. Two two instance pipelines (edge: stdin json -> socket sink `encoding.codec = "facet"`; aggregator: socket source `decoding.codec = "facet"` with `route_node` -> console json), the committed `vector.toml`/`vector_edge.toml` pattern with policy and port swapped per soak; fed at ~5 events/s each by the committed feeders. Soak A: `fusion_triage.md` (4 fields). Soak B: `big_values.md` (3 fields, thresholds spanning 10^2 to 10^12, 5% of events spiking to 10^13..10^15, past 2^53). Durations from the decoded events' own timestamps; wire cost measured by replaying a 1,000 event decoded sample through prismpath-preflight (quantization is idempotent on representatives, so the sample's framed bytes are the wire's).

**Result:** soak A: 556,477 decisions in 30 h 57 m, 2.000 B/event framed, ~1.11 MB total wire. Soak B: 486,965 decisions in 27 h 05 m, 1.466 B/event framed, ~0.71 MB total wire; route distribution baseline 36.32% / throttle 17.72% / elevated 16.40% / slow_path 14.97% / degraded 7.64% / exfil_alert 3.75% / watch 3.21%, matching the same distribution sampled at one sixth of the run within a tenth of a point per route. Memory per Vector instance 56 MB and flat across the full run (debug builds). Combined: 1,043,442 decisions, zero errors of any kind. **Honest scope:** loopback TCP on one host, not a real link; ~5 events/s per pipeline is a soak cadence, not a throughput ceiling (the codec's per event cost is measured elsewhere: #104 on MCUs, 132 to 182 ns in kernel for evaluation); soak A's route node is the uniform intake hop, so its distribution is intentionally degenerate and discrimination is carried by soak B; decoded outputs carry representatives, not originals, by design; debug build binaries, so the flat 56 MB is an upper bound story, not a size claim. Staged here, not yet OTS anchored. Provenance: `integrations/vector/soak/` (`RESULTS.md`, `big_values.md`, `feeder_fusion.py`, `feeder_big_values.py`); fork branch `facet-codec` build of Vector 0.57.0; `prismpath-rs 0.1.0` / `prismpath-telemetry-rs` on crates.io.

### #106 — the #89 negative-literal re-sweep, hardware half: byte-identical image re-certified on the physical Zynq-7020 fabric (August 2026)

**Claim:** the negative integer literal classifier change (#89) is confirmed harmless all the way to silicon. In simulation the RTL now certifies the re-swept subset, and on the physical fabric the incident_severity image, byte-identical to the pre-change one already resident, routes every sample identically to the reference engine. No certified number moves.

**Method:** two halves. (1) RTL sim (`prismpath-hw/tb/`, cocotb 1.9 / Verilator): the interpreter re-certifies **124/1,079 predicate + 6/27 engine** vectors on corpus v2 after the classifier change (the tb had a path-bitrot bug that had silently stopped the gate running since the repo layout change; fixed in `45a8695`). (2) Physical fabric: the Zynq-7020 (PYNQ-Z2, overlay `ppt_overlay.bit` SHA `2b69d54d…`, unchanged) loaded the recompiled `incident_severity` image and it is **byte-identical** to the anchored one (SHA `314b033c…`, the same image cited in #75); a 44-sample deterministic sweep (both bools x 11 error_rate points across every ladder threshold) was routed in fabric over the board's MMIO server and every decision diffed against the reference engine.

**Result:** **44/44 fabric decisions match the reference**, zero divergence, across all four severity branches (watch 2, sev3_ticket 13, sev2_oncall 3, sev1_page 26); round trip 90.1/94.8/106.8 us min/median/max (including Linux, Python, and a two-hop SSH path). The recompiled image's SHA is unchanged, so the classifier change alters only which flows are *declared* Level M, never the bytes that run on the board, confirmed on silicon rather than argued. **Direct negative-literal fabric test (added same session).** Because incident_severity carries no negative literals, the sweep above proves the image is byte-identical and routes unchanged, but does not exercise a negative threshold on silicon. So a minimal flow `neg_literal_test` (`temp <= -20 -> deep_cold; temp <= -5 -> cold; else warm`) was compiled by the same untouched compiler (the literals appear in the image as signed atoms `val = -20`, `val = -5`), pushed to the board, and an 11-point temperature sweep straddling both thresholds routed in fabric: **11/11 match the reference**, both boundaries exact (`-20 -> deep_cold` on the `<=` edge, `-19 -> cold`; `-5 -> cold`, `-4 -> warm`), including `-100` and `+100`. Signed comparison is now certified on silicon directly, not inferred from image invariance. Log: `prismpath-hw/evidence/fabric_negliteral_2026-08-16.ndjson`; flow: `prismpath-hw/evidence/neg_literal_test.flow.md`. **Honest scope:** the fabric runs the incident_severity image (a 44-sample sweep), not the full 1,079-vector predicate corpus; the predicate-level re-sweep to 124/1,079 is the RTL/C-target tier (sim here, the C target certified live in prior rows). One field family, single hop, as with the other fabric rows. Staged here, not yet OTS anchored. Provenance: `prismpath-hw/evidence/fabric_resweep_2026-08-16.ndjson`, `prismpath-hw/tb/` (fixed `45a8695`); board PYNQ-Z2 Zynq-7020, PYNQ 2024.1, accessed over USB serial console + a Proxmox jump host.

### #107 — integrity under interference: the native codec pipeline emitted no wrong event across a 5-hour fault soak (August 2026)

**Claim:** under sustained intermittent-to-severe interference (loss, mid-stream byte corruption, TCP resets, blackouts), the native Facet codec pipeline in Vector never emits a malformed or untraceable event; malformed frames are dropped loudly, and everything delivered is route-correct. This is the integrity counterpart to the delivery-focused self-heal work (#101, facet-sink): here the codec pipeline has NO self-heal (reliability is the runtime's job), and the property under test is that degradation never becomes a silent wrong decision.

**Method:** `integrations/vector/interference/`. Two Vector instances (edge `encoding.codec=facet`, aggregator `decoding.codec=facet` routing at `triage` on the `big_values` policy) with a userspace fault-injection proxy (`fault_proxy.py`) between them, fed at ~20 events/s. Phased ~5.25h schedule (45m clean, 90m intermittent, 90m severe, 45m blackout cycles, 45m recovery); every injected fault timestamped and phase-tagged, every fed event teed to a ledger. Harvest: each decoded event's reconstructed fields are re-quantized to a cell-tuple and checked for (a) multiset containment in the fed ledger (no over-represented / manufactured tuple), (b) route self-consistency, and (c) parseability; decoder rejections counted from the aggregator log.

**Result:** 379,056 fed, 267,163 decoded (gap 111,893, entirely link faults: 24,634 blackout drops + 555 stalls + 446 resets + 341 corruptions + 53 blackouts). **0 manufactured events, 0 unparseable decoded lines, 0 route self-inconsistencies, decoded cell-tuples a subset of fed, 720 loud decoder rejections** of structurally malformed frames. **Statistical bound:** 0 wrong of 267,163 decoded bounds the detectable-wrong-event rate at **≤ 1.1e-5 (≤ 0.0012%) at 95%** (rule of three / one-sided Clopper-Pearson) — a ceiling on the rate, not a proof of zero; and it covers only the faults this harvest can detect (manufactured / unparseable / route-inconsistent), which is why the value-preserving byte-swap blind spot below is called out rather than folded into the bound. **Honest scope:** integrity not delivery (the gap is the link failing, which the codec does not repair; that is the Merkle self-heal layer, not in the Vector codec); byte corruption that stays a syntactically valid Fibonacci stream decodes to a different valid value and is out of the codec's scope (Merkle's job), and the multiset check cannot always distinguish such a value-preserving swap in a small cell space, so "0 manufactured" is corroborated by the 0 self-inconsistencies and 720 loud rejections rather than standing alone; loopback + userspace proxy on one host, not a physical contested link. Staged here, not yet OTS anchored. Provenance: `integrations/vector/interference/` (`RESULTS.md`, `fault_proxy.py`, `big_values.md`); fork branch `facet-codec` build of Vector 0.57.0.

### #108 — the frozen predicate corpus's declared subset, certified on the physical Zynq-7020 fabric: 124/124 (August 2026)

**Claim:** the FPGA fabric is not merely a one-policy demonstrator; the *same frozen conformance corpus* that certifies every other substrate now runs on the physical silicon. Every in-fragment predicate vector, including the boundary and edge-case probes, is evaluated on the Zynq-7020 and matches the frozen expectation, with the out-of-subset vectors itemized by reason.

**Method:** `prismpath-hw/fabric_corpus_bundle.py` (host) applies the exact subset filter of the C-target's `run_vectors.cert_predicates` to `prismpath/portable/conformance/predicates.json`: each case's predicate is compiled with the untouched compiler to a 2-node table image (`compile_predicate`), the context is subset-checked via `encode_regs` (out-of-subset raises `SubsetError`, counted with reason), and the in-subset (image, ctx, expect) triples are bundled. On the board, `fabric_corpus_cert.py` loads each unique table into fabric BRAM via the resident `PptOverlay.load_image` (overlay `ppt_overlay.bit` SHA `2b69d54d…`, unchanged; no bitstream reload between tables), writes the register context, and evaluates on silicon; `evaluate` returns None on no-match, so predicate truth is result-is-not-None. Every fabric verdict is diffed against the frozen `expect`.

**Result:** **124/124 in-subset predicate vectors pass on the physical fabric, 0 divergence**; 955/1,079 excluded with the same itemized reasons the C-target and RTL report (281 field-vs-field, 251 disallowed/unparseable, 141 constant-only, 119 string-ordering, 114 non-literal-collection, 36 substring-in, 11 non-scalar, 1 nested, 1 float). Per-eval round trip 88.1/108.2/225.8 us min/median/max (including Linux, Python, and the two-hop SSH path; the fabric evaluate itself is the 5 to 21 cycles of #73/#74). This is the fabric tier of the certification the C target (#72) and RTL run: same declared subset, same frozen corpus, now on the board directly rather than the C reference or Verilator. **Honest scope:** predicate/single-hop, the declared v0 subset (955 exclusions are the fragment boundary, not fabric limits); one field family per image; the round trip is dominated by the host path, not the fabric. Staged here, not yet OTS anchored. Provenance: `prismpath-hw/fabric_corpus_bundle.py`, `prismpath-hw/fabric_corpus_cert.py`, `prismpath-hw/evidence/fabric_corpus_cert_2026-08-16.json`; board PYNQ-Z2 Zynq-7020, PYNQ 2024.1, overlay `ppt_overlay.bit` SHA `2b69d54d…`.
