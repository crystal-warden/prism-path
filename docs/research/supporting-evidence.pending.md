### #117 — a signed policy drives a resident finite-state machine in the kernel: the stateful selector, conformance certified in-kernel 624/624 (August 2026)

**Claim:** the fixed in-kernel interpreter, unchanged, becomes a RESIDENT finite-state machine by holding its current node in a BPF map — so a signed policy is the *transition function* of a stateful kernel control plane, not just a per-packet decider. Each control packet is one discrete event; the resident posture persists across packets; no userspace is in the loop. This is the fabric switch-navigation pattern (a resident FSM whose transitions route on the policy) carried down to the eBPF decode plane.

**Method:** `ppt_select.bpf.c` is the certified `ppt_xdp` interpreter with its evaluator (`eval_atom`/`eval_prog`/`evaluate`) **byte identical** — so the frozen predicate conformance carries — plus ONE `sel_state_map` (a BPF array holding `cur_node`): the start node comes from the map, it evaluates, and writes the decided target back. The reset fails *closed* — a deliberate clean start is the loader writing `{start_node, inited=1}`, so a fresh load begins at the baseline, but an *uninitialized* state (a crash, a fresh or torn map, anything the loader did not set) falls to the **most restrictive** posture, never the baseline; a forced reload must buy `lockdown`, not `normal`. That fail-safe posture is a **signed `safe_node`** the policy declares (`safe: lockdown` in its frontmatter, carried in the image's flags-word high byte at offset 26 so it rides the Ed25519 manifest signature); an undeclared policy falls back to the last-node convention. A companion **migration lint** (`analysis` code `stateful-migration-undeclared`, in the broken-fixture corpus) refuses a resident selector — one declaring `safe:` — that does not also declare a signed hot-swap strategy (`migration: by-name` re-resolves the current node by name, `migration: reset-to` resets to the fail-safe), the same authoring gate as the `packing: spiral` baseline-last rule; the chosen mode rides a flags bit in the image, so it too is signed. The loader ENFORCES the strategy at swap time via its `selector_hotswap` primitive (read the resident state, `migrate_node`, swap the table, write the migrated node back under the state lock), using a signed per-node name-hash section (FNV-1a-32 per node, `FLAG_NODE_NAMES`); a `loader swapselector <new.ppt> <old.ppt>` command and `migrate_selector.c` both drive it. `migrate_selector.c` advances the resident posture to `lockdown` in-kernel under policy A, swaps to a reindexed policy B (same names, different indices), and checks the migration. The resident read-modify-write is serialized against multi-CPU concurrency with a **generation-counter CAS with bounded retry under a `bpf_spin_lock`** — snapshot `{cur_node, gen}` under the lock, evaluate unlocked, then commit only if the generation is unchanged; on a lost commit it re-snapshots from the new state and re-evaluates (up to 4 attempts), so a contender becomes a commit against fresh state rather than a lost event, and no transition is ever applied from a stale snapshot. The transition policy `posture_selector` (a normal → elevated → lockdown ladder, escalate/de-escalate clamping at both ends) is signed Ed25519 (key `d519348f`). `gen_selector_corpus.py` freezes **49 event streams / 624 events** — boundary walks that clamp at each end, every (posture, event) transition, hold events (out of range values that route to `else`), 30 seeded random streams, and a 200 event stress stream — recording the posture the resident interpreter reaches after each event as the reference, cross checked step by step against the C target (`interp.c`), the same two referee discipline the predicate corpus uses. `cert_selector.c` replays each stream through the loaded eBPF program via `BPF_PROG_TEST_RUN`, resetting the resident state per stream to a deliberate clean start, and diffs the kernel's posture trail against the frozen reference; a separate check drives the program from an *uninitialized* state to confirm the fail-safe reset. `smoke_selector.c` then drives the loaded program from 8 threads on separate CPUs against the one shared state map to stress the CAS serialization under real concurrency. Each committed transition also emits an audit **receipt** `{seq, policy_hash, prev_node, event, next_node}` to a BPF ringbuf; `receipts_selector.c` drains it while replaying the corpus, checks the log against the frozen reference, and Merkle-roots the batch.

**Result:** in kernel, **624/624 events match and 49/49 streams are clean** — the kernel reproduces the frozen posture trail exactly (Linux 6.17, `BPF_PROG_TEST_RUN`, no NIC). The C target agrees with Python at every one of the 624 reference steps, so three independent evaluators (kernel, C, Python) concur. A separate fail-safe check confirms the reset fails closed: from an uninitialized state map, one event lands the kernel on the most restrictive posture (`lockdown`, the last node), not the baseline — a forced reload buys lockdown, not normal. Under an adversarial concurrency stress — 8 threads × 20 000 events = 160 000 control events hammering the single shared state cell with no queue steering — the resident posture stayed a valid in-range state throughout, never torn (96 437 committed advances, 63 563 CAS drops with the 4-retry CAS, down from 118 701 single-shot); the lock plus bounded retry guarantees integrity and no stale-misapply, and the residual drops are the un-steered worst case, not a deployment throughput figure. Packing the selector and flipping the signed `safe_node` byte makes `verify_pack` fail with an image-hash mismatch, so the fail-safe posture is covered by the signature, not a bare convention. The audit-receipt log is complete and faithful: **624 receipts for 624 committed transitions, 0 mismatches** — every receipt reproduces the certified posture trail, carries the pre-state (`prev_node`), records the driving event, and binds to the loaded policy via a `policy_hash` (low 64 bits of the image sha256); the Merkle root over the batch is deterministic across runs and anchorable by a single OTS stamp. Swap-time migration is enforced by the loader: swapping a resident `lockdown` from policy A into a REINDEXED policy B re-resolves it by name to B's `lockdown` index (a raw index carry would misread it as `elevated`), the migrated state then drives B's FSM live in-kernel, and reset-to instead sends an in-flight posture to B's fail-safe. Deployed live end to end: attached to a veth in both XDP SKB and native/DRV driver mode, the selector advances its resident posture from REAL control packets (two escalate packets -> lockdown, generation 2), `sel_state` pinned on bpffs persists across separate loader invocations, and a hot-swap to the reindexed policy re-resolves the persistent lockdown by name to the new index with the generation counter preserved (the same resident state, migrated, not reset). The resident FSM pattern is substrate independent: the identical signed selector runs as a resident walk on the C interpreter, and (from the hardware work) on the fabric `ppt_nav` overlay in simulation; only the driver differs — a BPF map here, a register in fabric, a variable in a userspace loop. **Honest scope:** a prototype, certified in kernel on the GX10 dev station via `BPF_PROG_TEST_RUN` and additionally deployed live on a veth in BOTH XDP SKB (generic) and native/DRV driver mode (confirmed `xdp` not `xdpgeneric` via `ip -d`), where real control packets advance the resident posture and `sel_state` persists on bpffs across a hot-swap, but on a veth on the dev box (whose only physical ethernet is its management lifeline), not yet on a production NIC nor the Protectli deployment; one selector policy (the posture ladder), not a family; the corpus is decidable transition coverage, not an adversarial fuzz; the in-program lock guarantees state integrity and no stale-misapply, but strict global event ORDER for a multi-queue deployment comes from single-RX-queue steering (the kernel analog of the fabric clock), which the smoke test deliberately omits to characterize the worst case; the migration lint gates authoring, the strategy and the per-node name-hashes are signed, and the loader's `selector_hotswap` primitive (`migrate_node` + table swap + resident-state write) enforces the swap, driven by both a `loader swapselector` command and the `migrate_selector` harness against live kernel state, but pinning `sel_state` on bpffs to persist across invocations and attaching the selector to a NIC are the remaining deployment steps; the receipt `policy_hash` is a 64-bit prefix of the image sha256, stamped by the loader at load (`populate_maps` computes `sha256(image)`, verified to match `policy_pack`'s manifest `image_sha256`); the OTS anchor of the receipt Merkle root is still pending (owner-gated); this is a NEW capability (resident state in the kernel) distinct from the stateless net admission target, and its priority date OTS anchor over the corpus is stamped at publish, not yet.
