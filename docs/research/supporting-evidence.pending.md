### #117 — a signed policy drives a resident finite-state machine in the kernel: the stateful selector, conformance certified in-kernel 624/624 (August 2026)

**Claim:** the fixed in-kernel interpreter, unchanged, becomes a RESIDENT finite-state machine by holding its current node in a BPF map — so a signed policy is the *transition function* of a stateful kernel control plane, not just a per-packet decider. Each control packet is one discrete event; the resident posture persists across packets; no userspace is in the loop. This is the fabric switch-navigation pattern (a resident FSM whose transitions route on the policy) carried down to the eBPF decode plane.

**Method:** `ppt_select.bpf.c` is the certified `ppt_xdp` interpreter with its evaluator (`eval_atom`/`eval_prog`/`evaluate`) **byte identical** — so the frozen predicate conformance carries — plus ONE `sel_state_map` (a BPF array holding `cur_node`): the start node comes from the map, it evaluates, and writes the decided target back. The reset fails *closed* — a deliberate clean start is the loader writing `{start_node, inited=1}`, so a fresh load begins at the baseline, but an *uninitialized* state (a crash, a fresh or torn map, anything the loader did not set) falls to the **most restrictive** posture, never the baseline; a forced reload must buy `lockdown`, not `normal`. That fail-safe posture is a **signed `safe_node`** the policy declares (`safe: lockdown` in its frontmatter, carried in the image's flags-word high byte at offset 26 so it rides the Ed25519 manifest signature); an undeclared policy falls back to the last-node convention. A companion **migration lint** (`analysis` code `stateful-migration-undeclared`, in the broken-fixture corpus) refuses a **stateful** pack — one declaring `stateful: true` — that does not also declare a signed hot-swap strategy (`migration: by-name` re-resolves the current node by name, `migration: reset-to` resets to the fail-safe), the same authoring gate as the `packing: spiral` baseline-last rule; the chosen mode rides a flags bit in the image, so it too is signed. The loader ENFORCES the strategy at swap time via its `selector_hotswap` primitive (read the resident state, `migrate_node`, swap the table, write the migrated node back under the state lock), using a signed per-node name-hash section (FNV-1a-32 per node, `FLAG_NODE_NAMES`); a `loader swapselector <new.ppt> <old.ppt>` command and `migrate_selector.c` both drive it. `migrate_selector.c` advances the resident posture to `lockdown` in-kernel under policy A, swaps to a reindexed policy B (same names, different indices), and checks the migration. The resident read-modify-write is serialized against multi-CPU concurrency with a **generation-counter CAS with bounded retry under a `bpf_spin_lock`** — snapshot `{cur_node, gen}` under the lock, evaluate unlocked, then commit only if the generation is unchanged; on a lost commit it re-snapshots from the new state and re-evaluates (up to 4 attempts), so a contender becomes a commit against fresh state rather than a lost event, and no transition is ever applied from a stale snapshot. The transition policy `posture_selector` (a normal → elevated → lockdown ladder, escalate/de-escalate clamping at both ends) is signed Ed25519 (key `d519348f`). `gen_selector_corpus.py` freezes **49 event streams / 624 events** — boundary walks that clamp at each end, every (posture, event) transition, hold events (out of range values that route to `else`), 30 seeded random streams, and a 200 event stress stream — recording the posture the resident interpreter reaches after each event as the reference, cross checked step by step against the C target (`interp.c`), the same two referee discipline the predicate corpus uses. `cert_selector.c` replays each stream through the loaded eBPF program via `BPF_PROG_TEST_RUN`, resetting the resident state per stream to a deliberate clean start, and diffs the kernel's posture trail against the frozen reference; a separate check drives the program from an *uninitialized* state to confirm the fail-safe reset. `smoke_selector.c` then drives the loaded program from 8 threads on separate CPUs against the one shared state map to stress the CAS serialization under real concurrency. Each committed transition also emits an audit **receipt** `{seq, t_ns, policy_hash, prev_node, event, next_node}` to a BPF ringbuf — the `t_ns` (`bpf_ktime_get_ns()` at commit) puts the TIME axis inside the tamper-evident record; `receipts_selector.c` drains it while replaying the corpus, checks the decision trail against the frozen reference and the timestamps for monotonicity, and Merkle-roots the batch. Statefulness itself is an **opt-in signed profile** (like `packing: spiral`), not the substrate: a policy declares `stateful: true`, stamped `FLAG_STATEFUL` into the image, and the stateless `ppt_xdp` base stays the self-healing default — the evaluator is byte-identical either way, so one conformance oracle covers both and a mode never changes the decision.

**Result:** in kernel, **624/624 events match and 49/49 streams are clean** — the kernel reproduces the frozen posture trail exactly (Linux 6.17, `BPF_PROG_TEST_RUN`, no NIC). The C target agrees with Python at every one of the 624 reference steps, so three independent evaluators (kernel, C, Python) concur. A separate fail-safe check confirms the reset fails closed: from an uninitialized state map, one event lands the kernel on the most restrictive posture (`lockdown`, the last node), not the baseline — a forced reload buys lockdown, not normal. Under an adversarial concurrency stress — 8 threads × 20 000 events = 160 000 control events hammering the single shared state cell with no queue steering — the resident posture stayed a valid in-range state throughout, never torn (96 437 committed advances, 63 563 CAS drops with the 4-retry CAS, down from 118 701 single-shot); the lock plus bounded retry guarantees integrity and no stale-misapply, and the residual drops are the un-steered worst case, not a deployment throughput figure. Packing the selector and flipping the signed `safe_node` byte makes `verify_pack` fail with an image-hash mismatch, so the fail-safe posture is covered by the signature, not a bare convention. The audit-receipt log is complete and faithful: **624 receipts for 624 committed transitions, 0 mismatches** — every receipt reproduces the certified posture trail, carries the pre-state (`prev_node`), records the driving event, and binds to the loaded policy via a `policy_hash` (low 64 bits of the image sha256); each receipt also carries a **signed time axis** (`t_ns` = `bpf_ktime_get_ns()` at commit), monotonic across the batch, so the DECISIONS stay the deterministic oracle (they reproduce the frozen trail every run) while the time makes the full receipt per-session — the Merkle root over decisions+time is a per-session tamper-evident anchor, anchorable by a single OTS stamp. Swap-time migration is enforced by the loader: swapping a resident `lockdown` from policy A into a REINDEXED policy B re-resolves it by name to B's `lockdown` index (a raw index carry would misread it as `elevated`), the migrated state then drives B's FSM live in-kernel, and reset-to instead sends an in-flight posture to B's fail-safe. Deployed live end to end: attached to a veth in both XDP SKB and native/DRV driver mode, the selector advances its resident posture from REAL control packets (two escalate packets -> lockdown, generation 2), `sel_state` pinned on bpffs persists across separate loader invocations, and a hot-swap to the reindexed policy re-resolves the persistent lockdown by name to the new index with the generation counter preserved (the same resident state, migrated, not reset). The resident FSM pattern is substrate independent: the identical signed selector runs as a resident walk on the C interpreter, and (from the hardware work) on the fabric `ppt_nav` overlay in simulation; only the driver differs — a BPF map here, a register in fabric, a variable in a userspace loop. **Honest scope:** a prototype, certified in kernel on the GX10 dev station via `BPF_PROG_TEST_RUN` and additionally deployed live on a veth in BOTH XDP SKB (generic) and native/DRV driver mode (confirmed `xdp` not `xdpgeneric` via `ip -d`), where real control packets advance the resident posture and `sel_state` persists on bpffs across a hot-swap, but on a veth on the dev box (whose only physical ethernet is its management lifeline), not yet on a production NIC nor the Protectli deployment; one selector policy (the posture ladder), not a family; the corpus is decidable transition coverage, not an adversarial fuzz; the in-program lock guarantees state integrity and no stale-misapply, but strict global event ORDER for a multi-queue deployment comes from single-RX-queue steering (the kernel analog of the fabric clock), which the smoke test deliberately omits to characterize the worst case; the migration lint gates authoring, the strategy and the per-node name-hashes are signed, and the loader's `selector_hotswap` primitive (`migrate_node` + table swap + resident-state write) enforces the swap, driven by both a `loader swapselector` command and the `migrate_selector` harness against live kernel state, but pinning `sel_state` on bpffs to persist across invocations and attaching the selector to a NIC are the remaining deployment steps; the receipt `policy_hash` is a 64-bit prefix of the image sha256, stamped by the loader at load (`populate_maps` computes `sha256(image)`, verified to match `policy_pack`'s manifest `image_sha256`); the OTS anchor of the receipt Merkle root is still pending (owner-gated); this is a NEW capability (resident state in the kernel) distinct from the stateless net admission target, and its priority date OTS anchor over the corpus is stamped at publish, not yet.

**Provenance:** `prismpath-ebpf/ppt_select.bpf.c`, `prismpath-ebpf/posture_selector.md`, `prismpath-ebpf/gen_selector_corpus.py`, `prismpath-ebpf/cert_selector.c`, `prismpath-ebpf/smoke_selector.c`, `prismpath-ebpf/selector_corpus.json` + `.bin`, `prismpath-ebpf/STATEFUL_SELECTOR.md`, `prismpath-ebpf/loader.c` + `ppt_common.h` (safe_node plumbing), `prismpath/policy_pack.py` (signed `safe_node` + `FLAG_MIGRATE_BY_NAME` header fields + the generic per-node-attribute reframe of the former LED-only `FLAG_COLORS`), `prismpath/analysis.py` + `prismpath/tests/fixtures/broken/stateful_migration_undeclared.md` (the migration lint + its corpus fixture), `prismpath-ebpf/receipts_selector.c` + the `ppt_receipt` (now with the signed `t_ns` time axis) / `policy_hash` / `FLAG_STATEFUL` additions to `ppt_common.h` (ringbuf audit receipts + Merkle anchor + the opt-in signed stateful mode; mode-keyed lint reframe in `prismpath/analysis.py` + `FLAG_STATEFUL` in `policy_pack.py`), `prismpath-ebpf/posture_selector_v2.md` + `gen_migrate_fixtures.py` + `migrate_selector.c` + `migrate_{A,Bname,Breset}.ppt` with the `migrate_node` + `FLAG_NODE_NAMES` additions to `loader.c` / `policy_pack.py` (loader-enforced hot-swap migration); box Linux 6.17 / clang 18 / BTF; transition policy signed with the Ed25519 authority key_id `d519348f`.

### #118 — the ESP-NOW spiral mesh holds integrity under real 2.4 GHz interference: 0 wrong symbols across 8 phases (August 2026)

**Claim:** the decision-preserving spiral mesh (band tier every tick, magnitude refinement every 5th, over ESP-NOW) maintains **integrity** under real 2.4 GHz RF interference — across pulsed, sustained, and attenuating channels the band tier still carries the decision, liveness degrades gracefully, and **zero wrong symbols** are ever decoded. It is the physical, real-RF counterpart to #107's modeled Gilbert-Elliott burst soak.

**Method:** a three-node ESP32 spiral mesh flashed at B=1 (one tick per frame, so a lost band frame is exactly one lost tick and the per-directed-link loss over the six links is exact — each frame carries the sender's tick). `referee_interference.py` captures all three nodes over serial for 120 s per phase and measures, per directed link, band-tier delivery, the burst run-length histogram (the channel #107 modeled with a two-state Gilbert-Elliott process, now measured on real RF), band (class 1) vs refinement (class 2) survival separately, posture coherence, and **integrity** — any received symbol whose value disagrees with what the sender transmitted for that tick (ESP-NOW drops FCS-failed frames, so this must stay 0; a wrong symbol would be a real defect). Eight phases at 120 s each: two baselines, microwave (pulsed 2.45 GHz, water load, boards ~1 m away), hotspot (sustained co-channel Wi-Fi flood on channel 1), foil (one node wrapped), bowl, hand (deep fades), recovery.

**Result:** **0 wrong symbols in all eight phases (PASS)** — the mesh's counterpart to #107's "0 wrong events", now on live RF. Liveness degraded per mechanism, each by its own signature: the microwave stretched the maximum burst length from 2 ticks (baseline) to 8; the sustained hotspot flood hit liveness hardest (band delivery 91.9 %, coherence 56.2 %); recovery snapped back (band 97.5 %, max burst 3). The measured 2 → 8 max-burst progression is a real-RF burst channel to place beside #107's modeled Gilbert-Elliott lengths (the `burst_runlength_hist` frozen in each `phase_*.json`). **Honest scope:** coherence is the noisy metric here (ambient 2.4 GHz plus repeated node power-cycling during the session; recovery coherence returned to 68 %, not the baseline 82 %); the foil wrap was strong single-node attenuation, **not** a true partition — the USB monitor cable penetrates the wrap and carries RF, defeating the cage — and the hand-cup fades came out mild; one bench, one session; the certified claim is **integrity** (0 wrong under real interference), not a calibrated liveness figure.

**Provenance:** `prismpath-hw/spiral-mesh/referee_interference.py`, `interference_wifi.sh`, `INTERFERENCE_RUNBOOK.md`, and the frozen `phase_{baseline,baseline2,microwave,hotspot,foil,bowl,hand,recovery}.json`; three ESP32 nodes (ESP-IDF v5.4.4, B=1 build); companion to #107 (modeled Gilbert-Elliott burst soak).
