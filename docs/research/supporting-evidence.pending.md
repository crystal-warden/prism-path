### #101 — distributed decision fusion over the mesh: three ESP32 nodes each sense one channel and converge on one Level M posture, with a coordinated swap of the fused rule and fail safe under node loss and interference (August 2026)

*(Provisional. Captured while the fusion mesh is still under active test; contents mutable and not yet OTS anchored. Staged here, not folded into the frozen ledger, on purpose.)*

**Claim:** Three physically separate ESP32 nodes, each reading a different sensor, (a) produce one fused Level M decision that every node computes identically from bands shared over ESP-NOW, (b) coordinate-swap the fusion RULE itself across the whole fleet on command, and (c) stay fail-operational (escalate to TAMPER, or drop to DEGRADED, but never go silent) when a node dies or the link is jammed. The fused CRITICAL posture requires both rangefinders close AND the arming knob up, a region no single node can reach alone, and a sensor going dark while armed is itself read as a possible defeat. This is the decision fusion counterpart to the coordinated policy swap of #100: #100 moved one policy across the fleet; #101 both fuses independent sensor streams into one decidable decision and lets the fleet hot-swap the fusion rule that produces it.

**Method:** `prismpath-hw/mesh-fusion/`. The same three ESP-WROOM-32 boards as #98 and #100, one binary (`ppt_fusion_mesh.c`) flashed to all three; each board selects its role by matching its own Wi-Fi MAC against a baked `ROLES[]` map (slot 0 ToF `tof-A`, slot 1 ToF `tof-B`, slot 2 pot `arm`). Two nodes read a VL53L0X rangefinder over I2C (GPIO21/22); the third reads a potentiometer on GPIO35 (ADC1, since ADC2 is unavailable while Wi-Fi is up). Each node projects its raw reading to a 0..3 band in plain code, broadcasts `{slot, band}` over ESP-NOW every 200 ms, and holds the latest band from all three slots (one sensed locally, two received). The fused decision is the decidable part: a 320 byte `.ppt` compiled by `gen_fusion_mesh.py` from a three field Markdown flow (`tof_a`, `tof_b`, `arm`) whose edges include the stale-aware escalation rules, evaluated by the byte exact interpreter every substrate certifies; the winning edge is the posture (CRITICAL when `tof_a <= 1 and tof_b <= 1 and arm >= 2`, WARN on a single close or lightly armed sensor, OK otherwise; a slot unheard within 1500 ms reads a STALE sentinel band (8) that the same signed table escalates to TAMPER while armed, or drops to DEGRADED otherwise, so the fleet is fail-operational rather than fail-silent). Two pre-vetted fusion policies are baked (A arms at knob band >= 2, B tightens to >= 3), each tagged with a 32-bit FNV-1a id. Poking one node over USB with `R` makes it coordinator for a two-phase commit: PREPARE broadcasts the target table + id, each follower re-hashes it and checks the id is on its baked allowlist `{A, B}` before staging and ACKing, the coordinator COMMITs only on a two-node quorum, and every node applies the staged rule at its own `local_now + 120 ms`. Hardening was exercised two ways: a node held in reset (dropout), and a UART command that drops a settable percentage of received verdicts (`0`..`9` set 0 to 90%, `X` sets a 99% blackout; the PREPARE/COMMIT control plane is never dropped). Host script `orchestrate_fusion.py` streams and times every node's posture.

**Result:** live and reproducible on the three boards. **Fusion:** with the sensors moved, all three nodes tracked the same three bands and the same posture at every tick, converging within the roughly 80 ms broadcast phase and never disagreeing; the fused transition into CRITICAL landed exactly when both ToF bands fell to 1 or below on all three, matching the table's boundary line for line, LEDs in lockstep. **Coordinated rule swap:** a single `R` drove PREPARE seq=1 target=fusion-B, both followers `PREPARE ok ... staged, ACK`, coordinator `2 ACKs COMMIT`, then all three `FLIP -> fusion policy B` at epoch 1 with a host observed spread of about 2 to 4 ms (3/3), each follower having re-hashed and allowlist-checked the pushed rule before staging. **Fail-operational under node loss:** holding tof-A in reset drove the other two, once its band aged past the 1500 ms window, to read `a=8` (STALE) and, with the knob armed, escalate to TAMPER while still fusing the live rangefinder and the knob (never blank), returning to normal fusion within about 0.2 s of the node coming back. The escalation is decided by the signed table on the sentinel input, not an ad-hoc code path. **Under interference:** the same freshness mechanism ages unheard slots into the STALE sentinel, so heavy packet loss degrades or escalates the posture rather than going quiet. (An earlier fail-silent build instead reported `waiting` and killed the LED under both a dropped node and heavy loss, holding 100% fused through 50% loss; that behavior is superseded, and a full drop-sweep re-measurement on the fail-operational build is a pending number.) **Honest scope:** this is a provisional snapshot captured while the mesh is still under active test; the fusion policy, the projection thresholds, and these observations are mutable and not yet OTS anchored, which is why this row lives in the staging file rather than the frozen ledger. It is a demonstrator, not a certified sweep: the millisecond spreads are the broadcast and commit cadence, not measured tight bounds; agreement and degradation were read from a short window and line counts, not a long fault matrix; the per node projection is plain code and only the fused decision and the swapped rule are certified tables; the interference is a simulated data-plane drop (esp_random over the received verdicts, control plane exempt), not real RF jamming; and the mesh is unauthenticated ESP-NOW with an FNV-1a allowlist standing in for a signature, so the Ed25519 on the mesh follow on named in #100 applies here too. Provenance: `prismpath-hw/mesh-fusion/` (`ppt_fusion_mesh.c`, `gen_fusion_mesh.py`, `main/fusion_mesh_table.h`, `orchestrate_fusion.py`); three ESP-WROOM-32 boards, two VL53L0X sensors, one potentiometer; ESP-IDF v5.4.

### #102 — Ed25519-signed policy hot-swap on the ESP-NOW mesh: the FNV allowlist stand-in replaced by a real signature gate with an anti-rollback version floor (August 2026)

*(Provisional. Staged here, not folded into the frozen ledger, on purpose.)*

**Claim:** the coordinated fleet policy swap of #100 now authorizes each pushed policy with an Ed25519 signature verified on-device, plus a monotonic version floor that rejects rollback and replay. A follower stages a pushed table only if the signature verifies against the baked authority public key AND the version exceeds its persisted floor; the two-phase commit, quorum, and atomic flip are otherwise unchanged. This is the cryptographic gate the FNV-1a id/allowlist explicitly stood in for.

**Method:** `prismpath-hw/mesh/`. `gen_mesh_tables.py` is the fleet authority signer: it signs each policy's `"PPTM1" || key_id || version || len || table` message with an Ed25519 key (private seed `authority_ed25519.key`, gitignored, created on first run) and bakes the 32-byte public key, a per-table 64-byte signature, and a monotonic version (A=1 permissive, B=2 tightened) into `tables.h`. On the node, `ppt_mesh.c` reconstructs that message and verifies it with vendored Monocypher 4.0.2 (`crypto_ed25519_check`, RFC 8032, public domain) against the baked pubkey, and requires the version to exceed an NVS-persisted floor; the PREPARE frame carries the version and 64-byte signature (about 161 bytes for the 84-byte demo table, under the 250-byte ESP-NOW cap). Before flashing, a host cross-check confirmed the Python signer and the vendored Monocypher agree byte for byte (real signatures verify; a tampered table, a corrupted signature, and a version mismatch all fail). Re-cert harness `recert.py`; the main task stack was raised to 8192 for the verify.

**Result:** re-certified live on the three ESP-WROOM-32s. The signed tighten A(v1) -> B(v2) is accepted (signature valid, version fresh), acknowledged by a two-node quorum, and the fleet flips together to B v2 at a host observed spread of 4.5 ms (3/3). The negative matrix all rejects with the fleet held on B: a rollback B -> A (v1 <= floor v2) is refused as `rollback/replay`, a byte-flipped table is refused as `bad Ed25519 signature`, and a corrupted signature is refused as `bad Ed25519 signature`; no unexpected flip occurs. **Honest scope:** provisional, staged, not yet OTS anchored. A demonstrator, not a certified sweep: one authority key and two policies; the version floor is a single monotonic u32 in NVS (a `Z` test command clears it for a repeatable run); the negative injections are driven from one node by test commands (`T`/`W`) rather than a distinct rogue radio; and the 4.5 ms spread is the commit-plus-fixed-delay cadence, not a clock-synced bound. The fusion mesh's rule-swap (`mesh-fusion/`, #101) still uses the FNV allowlist; porting this gate there is the named follow-on. Provenance: `prismpath-hw/mesh/` (`gen_mesh_tables.py`, `main/ppt_mesh.c`, `main/tables.h`, `main/monocypher*.{c,h}`, `recert.py`); three ESP-WROOM-32 boards; ESP-IDF v5.4; Monocypher 4.0.2.
