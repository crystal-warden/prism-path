# PrismPath — session handoff, 2026-07-29

You are picking this up cold. This document is **orientation and current state**, not a re-explanation
of the architecture — the repo is doc-rich and the deep material is listed under "Where the truth
lives". Read this, then that, then the code.

---

## 1. What PrismPath is, in one paragraph

A framework where **flows are Markdown documents** and the engine that runs them is small, portable,
and specified as data. A flow is a set of `## node` headings joined by `-> target: condition` edges;
conditions are either **deterministic** (`when x > 3`, evaluated in a sandbox with no `eval`), **error**
edges, **event** edges, or **semantic** ones that need a model tier. A flow whose reachable edges are
all decidable is **portable** — it runs anywhere the kernel runs, with no embedder and no LLM, and the
kernel *refuses* a non-portable flow rather than guessing. On top of that sits a **guard**: a safety
floor expressed as a policy document whose language has no permitting verb, so weakening it is
unsayable rather than merely forbidden.

The commercial shape is open-core: the kernel and spec are the credibility artifact; the paid surface
is the connector/adapter catalog and the governance layer around it.

## 2. The single most important thing to understand

**The conformance corpus IS the specification.**
`prismpath/portable/conformance/` holds 1,067 predicate vectors and 27 engine fixtures, generated from
the Python reference. Any implementation claiming to be a PrismPath kernel must pass **every case
bit-for-bit**. This is not a test suite that happens to exist; it is how the spec is written down, and
it is why a second implementation is possible at all.

As of today there are **three conformant implementations**, and every pytest run re-certifies all
three:

| implementation | status | gate |
|---|---|---|
| Python reference (`prismpath/`) | source of truth | `test_conformance_vectors.py` — committed vectors must match a fresh regeneration |
| `portable/prismpath.mjs` | **CONFORMANT** 1067/1067, 27/27 | `test_portable_conformance.py` |
| `prismpath-rs/` | **CONFORMANT** 1067/1067, 27/27 | `test_rust_conformance.py` (new today) |

```bash
PYTHONPATH=. python -m pytest prismpath/tests/ -q          # all three gates
cd prismpath-rs && cargo run --bin conformance -- ../prismpath/portable/conformance
```

**`prismpath-rs` is now certified on a second platform.** It was re-run on Apple Silicon (M4) under
**both macOS 15.6 and 26.6** and reports **CONFORMANT** (1067/1067, 27/27) on each. The corpus was
built to be a portable specification; it has now been shown to be one across two architectures and
two OS versions, not just two languages on one box.

A related cross-platform result from the consumer side is worth knowing here, because it constrains
what a conformance claim may rest on: **f32 embedding output is numerically equivalent but not
byte-identical across ARM implementations** (~1 ULP; candle reorders differently on M4 vs GB10). The
predicate corpus is unaffected — it is exact-valued — but **any future numeric conformance vector must
carry a tolerance, not a digest.**

If you change semantics, you regenerate the vectors (`python portable/gen_conformance.py`) and **the
resulting git diff is the spec-change review.** Do not "fix" a port to match a changed reference
without that diff being deliberate.

## 3. What changed in the last session (2026-07-29)

### prismpath-rs went from NOT CONFORMANT to CONFORMANT

It was certified on 2026-07-28 at **608/1067 predicates, 0/27 flows** — the report called it "one
implementation and one sketch": a string-splitting evaluator handling two token shapes, no flow
parser, one of four engine output fields. That report's itemized gap list became the work plan, and it
was executed in dependency order as a guided port of the `.mjs` kernel:

1. **Evaluator** — real tokenizer + recursive-descent parser onto an AST, plus the Python-semantics
   primitives (`py_truthy`, `py_eq`, `py_order`, `py_in`, `compare_op`), escape tables, Python-keyword
   rejection, and AST-depth accounting. **1067/1067 on the first full run.**
2. **Flow parser** — Markdown + YAML frontmatter with Python `splitlines()` boundaries. The three line
   patterns are hand-rolled so no regex dialect's `\s` gets a vote.
3. **Engine** — portability refusal, error tier, `needs_human`, `wait`/`spawn` suspension, and the
   `{path, stopped, pending_node, spawn}` contract.

The only post-evaluator fix was in the **harness**, not the kernel: `JSON.stringify(1.0)` is `"1"`, so
integral floats must serialize as integers or the spawn fixture fails on notation alone.

**The gate was proven able to fail** — deliberately breaking boolean-numeric equality produced 13
divergences and NOT CONFORMANT; reverting restored the pass. `prismpath-rs/CONFORMANCE.md` carries the
re-certification with the old report preserved as an appendix.

### `run_observed` — the observation seam

The `.mjs` engine had an `onStep` hook; the Rust port had skipped it as conformance-irrelevant. It now
exists at parity (`run_observed`), called at the reference's exact checkpoint sites.

**This is a deliberate architectural boundary, and it answers a question that will come up again:**
telemetry, audit trails, login, progress UIs are **host** capabilities that watch through this hook.
They do **not** go inside a kernel. A capability grown in one implementation and not the other forks
the spec the corpus froze — which would destroy the interchangeability that is the whole asset.

> **Ruling on record (2026-07-29).** Asked whether one kernel should serve B2C and the other the
> licensing track, the answer was **no**. Kernels are selected by **runtime** (`.mjs` where JS runs,
> Rust where native runs), never specialized by feature. The licensing pitch is *"here is the spec as
> data, here are certified implementations, integrate whichever fits your stack"*; differentiation
> lives in the BSL platform that wraps the kernel.

### P1's operating point is now frozen in a lockfile

`prismpath/gen_p1_lockfile.py` emits `policies/p1_lockfile.json`: the prohibited-intent centroids, the
threshold, the fingerprint of a fixed probe, the embedder identity (**including runtime and
precision** — the same weights under a different runtime are a different numeric contract), reference
**decisions** for real corpus cases, and parity vectors for consumers that cannot run the embedder.

Three defects surfaced while wiring a consumer to it, and the first one is the transferable lesson:

1. **Centroids were not unit-length.** A centroid is the *mean* of unit vectors, so ‖c‖<1, and any
   consumer scoring with a plain dot product under-scores every input by `1/‖c‖` and **under-blocks**
   (a paraphrase the reference scored 0.79 scored 0.67, crossing the threshold). Fixed by storing
   normalized centroids — cosine is scale-invariant, so no measured number changed and the naive
   implementation became the correct one.
2. **⭐ The fingerprint check stayed green through all of it.** It compares two raw embeddings and is
   structurally blind to how scores are derived from them. *An artifact-integrity check never
   substitutes for an outcome check.* Hence `reference_scores` in the lockfile.
3. **`layer_hash` depended on a language's float formatting** — `json.dumps` writes
   `{"a": [1.0, 2.0]}` and goes exponential below 1e-4; `JSON.stringify` writes `{"a":[1,2]}` and waits
   until 1e-7. Both sides reported themselves healthy while writing records that could never be
   correlated. **Now v2: a byte encoding** (domain tag, NUL-terminated strings, u32 lengths,
   big-endian IEEE-754 f64). Parity holds *by construction*; the consumer reproduced it first run.

### Phase 0 + hygiene

`phase0/cpu_adjudication_bench.py` records the CPU-adjudication finding (plumbing works; **quality is
the wall** — 3B 1/3, 7B 2/3, only the 31B on GPU 3/3, and the failure is hardware-independent), and
the compliance adapter's endpoint/model are now env-overridable. `prismpath-rs/target/` was untracked
(333 object files had been committed).

## 5. Methodology this repo holds itself to

These are not style preferences; violating them has produced real defects here, each documented at the
site.

1. **Guarantee by grammar > by analysis > by measurement.** The safety floor is a policy grammar with
   no permitting verb, so bypass is *inexpressible*. Routing is a flow, because there
   expressiveness + lint is the right trade. Don't convert the floor into a flow.
2. **Claims attach to the floor, not the ceiling.** Anything model-based is a tier-conditional
   *enhancement*; the compliance claim rests on hardware-invariant P0. "Our safety classification is
   stronger on expensive computers" is the sentence that dies in front of a regulator.
3. **Fail to floor, loudly, attested.** Verification failure *disables* an enhancement rather than
   running it unverified. Claim-preserving by construction, because of (2).
4. **Pre-register a measurement before running it**, with predictions and a **control stratum** that
   can invalidate the run. Ours came back 0.19 instead of 0.00 on run one and correctly invalidated
   everything. Amendments are append-only; misses are recorded, *including misses in the direction that
   flatters the layer* — the direction nobody checks.
5. **Never build a classifier from its own acceptance test.** Centroid exemplars are asserted disjoint
   from the frozen corpus programmatically, not remembered.
6. **Sweep a threshold; never pick one.** A chosen operating point invites tuning until the numbers
   flatter the layer.
7. **A control set you tuned against is a dev set.** Tuning may only use `dev`; the holdout is read to
   *report*, never to *decide*. If a change is ever made in response to a holdout result, record it
   and demote the holdout.
8. **Formatters must not touch control artifacts.** Prettier silently reformatted a vendored safety
   policy; policies and frozen vectors are in `.prettierignore` and hash-pinned.
9. **"Cryptographic" stays in the drawer** until anchoring round-trips. "Attested" and "auditable" are
   fine once the trail is wired. Never "verified" or "jailbreak-resistant" for a deterministic floor.

## 6. Open work, honestly stated

**Known limits of the guard, published rather than hidden:**

- **`roleplay` bypass sits at 1.00** — fictional framing defeats P0 *and* P1 together. Unmitigated, and
  no mitigation designed. This is genuinely hard and must not be quietly dropped from claims.
- **`translation` 0.98** — the embedder is English-only.
- The FP cliff is **steep** (0 false matches @0.75 → 8 @0.70 → 25 @0.65), which is the operational
  argument for lockfile pinning plus fail-to-floor.
- The benign corpus is **157 cases, one author, one domain, one embedder**. Better than 41 and still
  small. **A second author is the stated prerequisite for further threshold work.**

**Other open items:**

- P1 is recommended as **flag-mode** on first deployment, despite the evidence supporting deny for
  paraphrase/euphemism behind the lockfile gate. No field data yet.
- **`layer_hash` v2 fixed the symptom cleanly, but consider whether the reference should adopt a
  language-neutral canonical form for other hashed artifacts too** — the class of bug (a language's
  float repr inside a hash preimage) can recur anywhere a third implementation appears.
- `prismpath-rs` implements the **kernel**, not the guard. `safety.json` in the corpus dir belongs to
  P0, which has no Rust implementation. Do not let "the Rust kernel is conformant" drift into a claim
  about the safety boundary — `CONFORMANCE.md` §"Scope boundary" says this explicitly.
- Branch is `guard-onion-layer`, not `main`. Merge is a decision, not an oversight.

## 7. The seam with Journeyman

**PrismPath is a separate project that Journeyman consumes.** That boundary is a standing ruling, and
it decides where new code goes:

- Contract-**defining** code lives here: the guard grammar, the `layer_hash` layout, the lockfile
  generator, the measurement protocol, the reference implementations.
- Journeyman **consumes versioned artifacts**: it vendors `p1_lockfile.json` verbatim, vendors the
  `.mjs` kernel and the corpus, ports the runtime contract, and pins parity against this reference. It
  never generates, tunes, or redefines.
- A contract change is a PrismPath change **first**, with its own commit here; the Journeyman side is a
  consumer update.
- Decision test for new code: *would a second consumer of PrismPath need this?* Yes → here. No →
  Journeyman.

`prismpath-rs/` stays inside this repo despite the one-project-per-repo rule: it is not a project, it
is a second kernel of the *same spec*, and the conformance loop is tight only because they are
co-located. A repo boundary through the middle of a spec-and-its-implementations loop would create the
version skew the corpus exists to prevent.
