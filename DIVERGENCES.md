# Where the Rust crates differ from the Python reference

Python is the reference. Each line is a place where a Rust crate answers differently on purpose, with the reason, and the test that holds the difference. Anything not listed is held to Python by a frozen corpus or a cross language test, and a difference there is a defect.

| Place | Python | Rust | Why, and where it is held |
|---|---|---|---|
| The host's `active_unreadable` event for a record that cannot be read | the text is the JSON decoder's | the text is the Rust error's, and a number beyond the double range is worded `1e+400` | the wording is a library's, not the protocol's; `prismpath-hotswap-rs/tests/test_host_corners.rs` |
| A verified manifest whose `version` is not an integer | raises, or compares by Python's rules | `HostError::BadManifest`, nothing changed | the same; `test_host_corners.rs` |
| `PolicyHost.anchor_attestations` | stamps the leaves with the external `ots` program | absent | the crate drives no process; the Merkle root and every proof are there |
| An error a worker returns as a plain message | the flow's `error_type` is the exception's class name | the kind `Error`; a `WorkerError` names its own kind | a Rust closure has no exception class; `prismpath-rs/tests/test_engine_cross_language.rs` |
| An integer of the Facet wire, a receipt field or a reading beyond 64 bits | read at any width | `ReceiptError::Overflow` or `ConcentratorError::Overflow`, and a stream id beyond 64 bits is an unknown stream | the wire fields are `u64`; the corpora list such a case under `wide` and `prismpath-telemetry-rs/tests/test_cross_language.rs` holds it |
| An integer literal beyond 2^53 minus 1, or a float beyond the double range, in a flow's predicates | the contract is derived | `derive_contract` returns an error | no engine holds the number exactly; `prismpath-rs/tests/test_contract.rs` |
| The digits of other scripts, and an integer beyond 64 bits, in `PRISMPATH_MAX_FLOW_BYTES`, `PRISMPATH_MAX_NODES`, `PRISMPATH_MAX_EDGES` | `int()` reads them | refused | the corpus holds the strings both read alike; `prismpath-rs/tests/test_parse_limits.rs` |
| The receipt verifiers | read what Python reads | refuse a small order key, a boolean for an integer, a flow that is not UTF-8 | the list is in `prismpath-hotswap-rs/README.md`; each fails closed and none accepts what Python rejects |
| The private test keys of a core run (`core_evidence produce --keys`) | PKCS8 PEM, as `swap keygen` and `ledger keygen` write them | the raw 32 byte seed, as the hot swap crate's `keygen` writes it | each language signs with its own key files; a run holds only the raw 32 byte public keys, which are the same format, and each verifier checks the other's run (`prismpath/tests/test_core_evidence.py`) |
| The Rust core run verifier | checks signatures with `cryptography` | `verify_strict` | it also refuses a small order key or signature, as the receipt verifiers do; no honest key is affected (`prismpath/tests/test_core_evidence.py`) |
| `prismpath-preflight --privacy` | measures aggregation privacy, the decision-relevant field combinations a frame hides | the option is not accepted, the report has no privacy section | not yet ported; the JSON report is identical to Python's without it (`prismpath-preflight/tests/e2e.rs`) |
| A commit with a delay (B8) in `prismpath_hotswap_rs::dist::pep` | `Pep.commit(..., delay_ms)` flips at the PEP's monotonic time plus the delay | any delay but 0 is `PepError::Refused` and nothing changes | the delay belongs to the frame binding, which the crate does not build; `prismpath-hotswap-rs/tests/test_distribution_pep.rs` |
| The audit log of the Rust distribution PEP | signed after every append with the instance key (root statements beside the log) | the host's unsigned `AuditLog`, the same events | the crate has no root statement signer; the state records the PEP sends are signed by the instance key in both |
| The K2 scan of a Rust PEP's home, its raw seed | finds a PEM key file | also finds a raw 32 byte seed | the seed is the crate's own `keygen` format; `test_distribution_pep.rs` |
| The K2 scan of a Rust PEP's home, what it reads in a file | opens every file the walk lists, a FIFO included, takes one whose first 64 bytes begin `-----BEGIN` and hold `PRIVATE KEY`, and the key `cryptography` loads from it | opens only a regular file, its type checked before it is opened, reads it as bytes, takes one holding `-----BEGIN` and `PRIVATE KEY` anywhere, and checks every private key block on its own: a block with no end line is passed over, and the header lines of RFC 1421 before a block's base64 are skipped. So a trusted key after a public block, after an untrusted key, after a byte that is not UTF-8 or after an unterminated block is found | a scan that finds more only refuses more, and a FIFO no process writes cannot stop a start; `test_distribution_pep.rs` |
| The Rust PEP's state directory | read by the Python machine | not held to be read by the other runtime, though the file names and documents are the same | no corpus or cross language test opens one runtime's PEP directory with the other; the state records and envelopes are held both ways by `test_distribution_cross_language.rs` |
| Section 9.5, a runtime step that fails after its record is durable | decides under the PEP's release while the runtime may run another, and sends no record of the transition until a restart | `reconciling` as 9.5 says: the runtime is withdrawn at once, every decision, commit and rollback is refused with `dist:reconciling`, only a tick and a start try again, each record has status 3 and the entry of H14, a renewal never enters the state, a held release that falls lapses unrun, and provisioning over a runtime that does not withdraw is refused (P5). No action floor or fallback policy is built (section 21), so the withdrawal leaves the runtime running nothing | Python takes 9.5 in its own pull request (14b); `test_distribution_reconciling.rs` |
| The intent record (`pending.json`) of the Rust PEP | names a commit or a rollback and the release it makes active | also names a lapse, its cause, the release the runtime ran when the transition started and whether the runtime was withdrawn since (C7, C10); it reads Python's form, with those members absent | the same pull request; `test_distribution_reconciling.rs` |
| The epoch id a PEP reports (H9, H15) | `Pep.see_epoch` takes the bare epoch id of an `offers` answer or an epoch frame | takes none and reports 0 in every record, since it reads `/1` anchors only and does not build `trust.controller`, so it holds no controller key to verify a statement under (P4, K6) | the controller statement and its key come to both later. The Python controller on main accepts epoch 0 only while its own epoch is 1, its first heartbeat interval, and files `fleet:state-replay` after that, so `test_distribution_cross_language.rs` pins the controller's clock inside that interval; H6 says epoch 0 is no replay from a PEP that holds no controller key, which the controller takes in its own pull request (14b). `test_distribution_pep.rs`, `test_distribution_reconciling.rs` |
| The widening comparators of the Rust PEP | `prismpath.distribution.widening` orders `policy.core`, `egress.hosts` and `agent.zones` | compares `policy.ppt` and `gateway.routes` as any change larger and the derived artifacts as not larger, as Python does, and any other artifact only as unchanged bytes, so a change of one cannot be decided and counts as larger | the Rust rows are `host` alone, which compares only its table (W2); `pep.rs`, `test_distribution_conformance.rs` |
| `Pep::replace_trust` | the tests replace `pep.trust` in memory | only with the crate's `test-support` feature, which only its own tests turn on | a store changed under a staged release (case 50's C3 half) cannot be reached through the machine |
| A restart after a flip died past its active record | keeps the release it made active staged, so the same seq commits again and the kept release is lost | drops that staged release, so the commit is `dist:not-staged` and the kept release stays | Python's 9.5 pull request (14b); `test_distribution_pep.rs` |
| `PolicyHost::install_verified` and `withdraw` tried again after a death past their audit event | write the event again | write it once while the log's last event is that same event, member for member with the distribution envelope; a host restart writes `swap_incomplete` first, so after one the event is written again, and a withdraw with nothing active clears an install's intent | so a PEP retrying each tick does not grow the host's log; `swap` and `rollback` still write it again, as the host trace corpus holds; `host.rs` tests |
| The preflight Markdown report | a mismatch line shows the reading with `json.dumps` spacing, and the reasons of one line in Python's order | the reading in compact JSON and the reasons in Rust's own order | cosmetic, the JSON report is identical |
